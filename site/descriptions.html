Apps

Tahoe Explorer

Tahoe-100M is one of the largest single-cell perturbation datasets out there: 100.6 million rows, 2.29 gigabytes of parquet. Before I built this, exploring it meant writing a new query every time you had a question. Tahoe Explorer lets you filter by cell line and drug, see the summary instantly, and copy out the exact R or Python code that produced it. The trick is that every summary runs as a DuckDB query, so the raw cells never have to load into R memory. You leave with an answer and a reproducible recipe, not just a picture.

GeneScout

GeneScout takes a list of candidate genes, variants, or perturbations, plus a disease you care about, and comes back with a ranked, cited shortlist of what looks plausible and why. It runs on an LLM behind the scenes (Gemini by default, though that is swappable), but every claim has to clear a citation gate first: no citation, no claim. It is a research tool, not a clinical one, and I built it to be honest about that limit rather than to sound more certain than the evidence supports.

Plotomics Live

This is a 26-page gallery of GPU-accelerated visualizations, from oncoplots to Kaplan-Meier curves to a 1-million-point Xenium spatial view. What makes it interesting underneath: the R backend is 476 lines long, and only one of those lines touches the UI. Everything else, all the interactivity and rendering, is a React front end talking to Shiny through shinyreact, with data sent as compact binary blobs straight to the GPU instead of JSON. Every page also falls back to a classic ggplot2 render off the same computation, so nothing depends on WebGL support.

Recount Explorer

Recount3 has almost 19,000 uniformly processed RNA-seq studies sitting behind an API, and most people never look past the study they already know. Recount Explorer is a browser for that catalog: filter by organism, source, or size, load a study, and get its quality checks, gene expression, and a PCA plot without writing any code. It is the newest of these apps and the simplest idea: make the recount3 catalog something you can actually explore.

Variant Reviewer

Give this one gene and one variant, and it fans out to eighteen public APIs at once, MyGene, MyVariant, gnomAD, ClinVar, VEP, GTEx, STRING, Open Targets, and AlphaFold among them, then lays every answer out on a single page. There is a 3D structure viewer built in, and a ClinVar typeahead that starts prefetching as you type so the variant is already loaded by the time you finish. I built it because reviewing a variant properly used to mean a dozen browser tabs; now it is one page that loads while you read.

Gene List Builder

Start with a disease name. Gene List Builder resolves it to an EFO or MONDO term, queries seven gene-disease evidence sources in parallel, Open Targets, PanelApp, DGIdb, and Pharos among them, and dedupes everything down to one row per gene. You can tune how much weight each source gets and watch the ranking update live. When you're happy with the list, it exports a CSV plus a Markdown report that shows exactly where every gene's evidence came from.

DE Explorer

A differential expression explorer built on real, uniformly reprocessed TCGA lung cancer and airway RNA-seq data: adenocarcinoma against squamous cell against normal tissue. Move the significance threshold and every panel on the page follows, so you can see how one number changes the whole picture.

Signature Scoring

Instead of looking at one gene at a time, this app scores each TCGA breast cancer sample against all 50 Hallmark pathways and lets you contrast the clinical subtypes on that basis. A single gene's expression is noisy; a whole pathway score is a much steadier signal. Click into any pathway and it opens up to show you the individual genes driving that score.

Drug Perturbation

This one does connectivity scoring in the spirit of CMap and LINCS: rank a panel of compounds by how well each one reverses a disease's gene-expression signature, versus how well it mimics it, then break any hit down by cell line or dose. Worth saying plainly: the perturbation panel shown is a synthetic fixture grounded in TCGA-BRCA data, not real LINCS screening data. I built it to show the method clearly, not to make a drug-discovery claim I can't back up.

Genome Explorer

Recurrent breast cancer driver mutations from TCGA, placed in genomic context on hg19 through a real igv.js genome browser, not a static plot pretending to be one. Raise the recurrence filter to cut the noise, then click any variant and the browser zooms straight to it. It's also the one app in the family that ships the full matrix: both R and Python versions, in both Shiny and shinyreact.

Packages

biobouncer

biobouncer answers one question: is this identifier valid? Gene symbols, ontology terms, variant formats, database accessions, 48 identifier systems in total, checked either offline against known patterns and a cached snapshot, or live against the source. R, Python, and TypeScript all run against the same conformance test corpus, so the three implementations can't quietly drift apart and give different answers for the same input. It doesn't replace something like biomaRt or mygene; it's the gate that checks your input before it ever reaches them. It's on CRAN and PyPI now.

biohttp

biohttp is the HTTP layer underneath my other R packages that talk to biological web services. Calls return a result value instead of throwing an error, so a real failure and a merely-empty answer stay clearly distinct in your code. Circuit breaking, retries, throttling, and success-only caching are all on by default, so a flaky API doesn't take down whatever you're running. It's plumbing, not a product, but it's the plumbing that makes bioclients possible.

bioclients

bioclients is one client per biological database, 29 of them, from Ensembl and UniProt to gnomAD, Open Targets, and AlphaFold. Each client is split into two halves: the part that makes the request, and a pure parser that needs no network at all, which makes the parsing logic simple to test in isolation. Transport, retries, and caching are all handled by biohttp underneath, so bioclients itself only has to worry about what each API actually returns.

plotomics

plotomics is the GPU-accelerated visualization engine behind Plotomics Live: one TypeScript core, seventeen chart types from volcano plots to spatial views to genome tracks, wrapped three separate ways so the same code renders in a React app, an R Shiny app through htmlwidgets, or a Jupyter notebook through anywidget. Large data never goes through JSON; it moves as typed arrays straight to the GPU. It's on npm, PyPI, CRAN, and R-universe, because the whole point was to stop rebuilding the same charts three times in three languages.

biocohort

biocohort keeps the subjects, samples, and analysis outputs of an omics study in one validated object, instead of scattered across spreadsheets that drift out of sync. Species and assay are values in the data, not separate columns or classes, so the same manifest structure works whether you're tracking a human cohort or a mouse one, RNA-seq or proteomics. It also generates pipeline sample sheets and keeps a registry of what analysis ran on what, so you can trace a result back to the exact samples that produced it.
